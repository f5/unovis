Version `1.8` of _Unovis_ is here! It brings a new _Circular Bar_ component, sixteen new interactive gallery examples with ready-to-copy agent prompts, noticeably smaller bundles and faster builds thanks to direct imports, automatic crosshair tooltips, icons in _Donut_ charts, Svelte 5 support, a big batch of performance work in the core, and a long list of bug fixes.

We're excited to welcome our new first-time contributors to the Unovis community: [@Eg0r0k](https://github.com/Eg0r0k) and [@smonist](https://github.com/smonist). Huge thanks as well to [@50rayn](https://github.com/50rayn) for their continued contributions! 🎉

## Release Highlights

### 📊 New Component: Circular Bar
<img alt="Circular Bar" src="https://github.com/user-attachments/assets/ab1922a7-9858-40e9-a611-b1585d53e2b2" />

_Circular Bar_ is a new _Single Container_ component inspired by the Apple Health activity rings. Each data record becomes a petal-shaped bar growing from a central hole, drawn over a faded full-length background that shows the maximum:
- `innerRadius`, `barPadding`, `cornerRadius` and `innerCornerRadius` default to fractions of the chart radius, so the shape keeps its proportions at any size ([docs](/docs/components/CircularBar#bar-shape))
- `angleRange` supports partial and reversed layouts; one or two bars over the full circle fall back to regular arcs ([docs](/docs/components/CircularBar#angle-range))
- `value`, `maxValue` (an accessor, a number or a per-datum array), `barMinLength`, `sortFunction`, `color` and `showBackground`
- `icon` and `iconSize` place an icon at the inner end of each bar — an icon-font glyph, a Unicode symbol or a `#href` to a symbol in the container's `svgDefs` ([docs](/docs/components/CircularBar#icons))

Check out the [documentation](/docs/components/CircularBar) and the new gallery example: [Seven readings, seven reference values](/gallery/view?collection=Circular%20Charts&example=basic-circular-bar-chart).

### 🖼️ Gallery: Sixteen New Interactive Examples and Agent Prompts
<img alt="Gallery" src="https://github.com/user-attachments/assets/a98e4572-b1bf-434f-97b1-b03695d47492" />

The [gallery](/gallery) grew by sixteen examples built on real datasets, each with React, Angular, Svelte, Vue, Solid and vanilla TypeScript implementations, data notes, and light and dark previews. Among them: [A week on the electricity grid](/gallery/view?collection=Composite%20Charts&example=electricity-grid-dashboard) with a synchronized crosshair and an overview brush, [Earthquakes across linked views](/gallery/view?collection=Maps&example=earthquake-explorer), [Where does U.S. energy go?](/gallery/view?collection=Sankey&example=energy-flow-sankey), [Inside the Unovis dependency graph](/gallery/view?collection=Network%20Graph&example=dependency-explorer), [Penguin body-mass distributions](/gallery/view?collection=Boxplot&example=penguin-distributions), [When does New York ride?](/gallery/view?collection=Heatmaps&example=bike-demand-heatmap) and [Three cities, readable without color](/gallery/view?collection=Line%20Charts&example=patterned-temperature-lines).

Every example page now has a **Copy prompt** button next to _Open in StackBlitz_: it copies a prompt, tailored to the selected framework, that asks a coding agent to recreate the chart in your project. For agents reading the docs directly, the website now publishes an [`llms.txt`](https://unovis.dev/llms.txt) index with fundamentals, framework guides, the MCP reference and generated API references for the core components and public types.

### 📦 Smaller Bundles and Faster Builds
The line chart bundle (`XYContainer`, `Line`, two `Axis`, `Crosshair`, `Tooltip` and `BulletLegend`, React, minified with esbuild) went from **68.7 KB** to **58.1 KB** gzipped — **15.5% smaller** than `1.7.1` — without any behavior changes:
- XY components import `scaleLinear` / `scaleSqrt` from d3-scale directly instead of going through the `Scale` object, which used to pull all sixteen d3 scales, `d3-time` and `d3-time-format` into every chart [#938](https://github.com/f5/unovis/pull/938)
- Containers use the native `ResizeObserver`; the `@juggle/resize-observer` polyfill is gone [#938](https://github.com/f5/unovis/pull/938)
- `d3-interpolate-path` is replaced with a small internal path interpolator used by _Line_, _Area_ and _Chord Diagram_ [#955](https://github.com/f5/unovis/pull/955)
- The unused `d3`, `d3-collection`, `geojson` and `tslib` dependencies are dropped: a clean install goes from 189 to 159 packages [#938](https://github.com/f5/unovis/pull/938)

**Direct imports.** All framework wrappers now import granular `@unovis/ts` subpaths instead of the root barrel, and `@unovis/svelte` exposes per-component subpaths like `@unovis/react`, `@unovis/vue` and `@unovis/solid` already did. Importing components from their defining modules lets your bundler skip the map, graph and layout dependencies it never needed to visit — in our measurements it processes **76% fewer modules**, builds **4–5× faster** and uses **70% less peak memory** [#876](https://github.com/f5/unovis/pull/876):

```ts
import { VisXYContainer } from '@unovis/react/containers/xy-container'
import { VisLine } from '@unovis/react/components/line'
import { CurveType } from '@unovis/ts/types/curve'
```

Every published package ships an `AGENTS.md` with the supported import paths for its framework, and a new CI check fails pull requests that grow the core bundles.

### 🎯 Crosshair: Automatic Tooltips
_Crosshair_ templates used to require a separate _Tooltip_ instance. _XY Container_ now creates one automatically when a `template` is set, so the common setup gets shorter; an explicitly configured _Tooltip_ in the same container still takes precedence ([docs](/docs/components/Crosshair#adding-a-tooltip)) [#964](https://github.com/f5/unovis/pull/964):

```tsx
<VisXYContainer data={data}>
  <VisLine x={x} y={y} />
  <VisCrosshair template={d => `${d.x}: ${d.y}`} />
</VisXYContainer>
```

Charts mixing stacked and regular series got a round of fixes too: per-circle `strokeColor`, `strokeWidth` and `opacity` and the container's `colorKeys` now follow the circle order, so each circle gets the style of its own series [#946](https://github.com/f5/unovis/pull/946), and when circles overlap, the one of the largest segment is painted last so a thin series no longer covers a thick one [#952](https://github.com/f5/unovis/pull/952).

### 🍩 Donut: Icons
<img alt="Donut icons" src="https://raw.githubusercontent.com/rokotyan/unovis/pr-assets/donut-icons/gallery-light.png" />

_Donut_ can now show an icon in the middle of each segment, the same way _Circular Bar_ does at the inner end of its bars ([docs](/docs/components/Donut#icons)) [#970](https://github.com/f5/unovis/pull/970):
- `icon` accepts a href to an SVG symbol defined in the container's `svgDefs` (e.g. `'#heart'`), an icon-font glyph or a Unicode symbol
- `iconSize` defaults to 50% of the arc width, capped at 15% of the radius and at 20px
- Icons hide when their segment is too small to fit them, follow their segments through data and layout transitions, and don't capture pointer events, so segment tooltips keep working
- New CSS variables: `--vis-donut-icon-color`, `--vis-donut-icon-font-family` and `--vis-donut-icon-font-weight`

### 🧅 Nested Donut: Percentage Layer Widths
`layerSettings.width` now accepts a percentage of the donut's radius, e.g. `'25%'`, so the hole keeps its proportions at any size ([docs](/docs/components/NestedDonut#layer-settings)). When the layer widths and paddings add up to more than the available radius, the layers are scaled down proportionally instead of drawing crossed arcs, and a transparent central background element lets you handle clicks in the middle via `NestedDonut.selectors.centralBackground` [#971](https://github.com/f5/unovis/pull/971).

### 🔵 Scatter: Dense Charts
_Scatter_ no longer creates a `<text>` element per point when there's no `label` accessor. On a chart of ~35k unlabelled points this cuts the DOM from 135,200 to 35,710 nodes and the mount time from 1,032 ms to 384 ms. For charts with more points than pixels, the new opt-in `cullOverlappingPoints` renders only the point that would end up on top of each pixel ([docs](/docs/components/Scatter#overlapping-points)). Thanks to [@50rayn](https://github.com/50rayn) for this contribution! [#932](https://github.com/f5/unovis/pull/932)

### 🗺️ Leaflet Map: MapLibre Worker Loading
Bundlers can't reliably resolve MapLibre's worker file, so _Leaflet Map_ now starts it from a `Blob` URL of a prebuilt worker bundled with _Unovis_. It works with every bundler without extra configuration. If your Content Security Policy doesn't allow `blob:` in `worker-src`, set `useMaplibreWorkerBlob: false` to load the same worker from a same-origin file instead ([docs](/docs/components/LeafletMap#maplibre-worker-loading)) [#926](https://github.com/f5/unovis/pull/926).

### ⚡ Performance and Core Improvements
A broad pass over the core and the containers removed several per-render performance cliffs [#949](https://github.com/f5/unovis/pull/949):
- Config merging no longer deep-clones the whole config on every `setConfig` / `updateContainer` — wrappers issue these on nearly every prop change, so animated charts paid a full deep clone per component per frame
- _Axis_ caches its auto-margin measurements and snapshots label rects once per tick collision pass, instead of building and throwing away a complete invisible axis on every render
- _Graph_ no longer forces a layout recalculation per node, and the data models shallow-copy their inputs instead of deep-cloning every node and link
- _XY Container_ computes scale domains once per render cycle and memoizes the expensive bleed getters of _Scatter_, _Timeline_ and _Sankey_
- _Crosshair_ bisects over cached sorted x values on `mousemove` instead of sorting the dataset on every frame
- `render()` is awaitable and the render scheduling logic is shared between the containers
- _Single Container_ validates extended sizing support and falls back to `Sizing.Fit` with a warning instead of crashing
- _Nested Donut_ layer backgrounds and _Radial Bar_ tracks tween their arcs by angle, so animated `angleRange`, width and data changes no longer produce invalid paths [#976](https://github.com/f5/unovis/pull/976)

### 🧩 Framework Updates
- **Svelte** — `@unovis/svelte` now supports **Svelte 4 and 5** from one package (`^4.0.0 || ^5.0.0`), including Svelte 5 applications using runes. Child `data` and config updates reliably redraw the chart, nested config mutations are detected, and an _Axis_ changing its `type` re-registers correctly [#957](https://github.com/f5/unovis/pull/957)
- **Vue** — the wrappers notify the container explicitly instead of relying on implicit proxy tracking: child data updates now trigger a render, config updates no longer double-render, and components don't throw when used outside a container. `@unovis/vue` also marks its entry as having side effects so webpack keeps the component CSS [#949](https://github.com/f5/unovis/pull/949) [#938](https://github.com/f5/unovis/pull/938)
- **React, Vue, Solid** — datasets and framework props are no longer passed into the component configs, and the `data` prop contract is unified across all five frameworks [#949](https://github.com/f5/unovis/pull/949)
- **React** — the `VisTimeSeries` CSS is injected only where the composite is used, which also fixes webpack builds rendering it unstyled [#938](https://github.com/f5/unovis/pull/938)
- **All wrappers** — generated from granular `@unovis/ts` imports; the five component generator drivers are consolidated into one shared implementation [#876](https://github.com/f5/unovis/pull/876) [#949](https://github.com/f5/unovis/pull/949)

## Worth Knowing
- The `@juggle/resize-observer`, `d3`, `d3-collection`, `geojson` and `tslib` dependencies (and `@types/d3`, `@types/d3-collection`) were removed from `@unovis/ts`. Apps that import `d3` or `tslib` without declaring them need to add them [#938](https://github.com/f5/unovis/pull/938)
- `@unovis/svelte` requires Svelte 4 or 5 [#957](https://github.com/f5/unovis/pull/957)
- _Treemap_ labels share one text baseline now, and the default `labelOffsetY` went from `4` to `1` to compensate. Explicit Y offsets keep their value, so custom spacing may need a ~3px adjustment [#961](https://github.com/f5/unovis/pull/961)
- _Nested Donut_ `%` layer widths are resolved against the donut's radius instead of `document.body` [#971](https://github.com/f5/unovis/pull/971)
- _Radial Bar_'s `maxValue` no longer falls back to `1` when it resolves to `0` [#947](https://github.com/f5/unovis/pull/947)
- `onCrosshairMove(undefined, …)` is no longer called when the initial data arrives, so examples feeding it back into `forceShowAt` keep their initial position on load [#936](https://github.com/f5/unovis/pull/936)
- A _Crosshair_ that sets only its own `y` in a container with stacked components used to line up with the container's color keys by accident and no longer does; set `colorKeys` on the _Crosshair_ to control them [#946](https://github.com/f5/unovis/pull/946)
